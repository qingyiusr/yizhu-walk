# 義起走讀！網站｜上傳與維護說明

## 檔案說明
- `index.html`：網頁本體（一般不用改）
- `data.js`：所有文字內容與設定（路線、地點介紹、獎勵說明、照片上傳網址）
- `apps-script.gs`：照片上傳到 Google 雲端硬碟的程式（貼到 Google Apps Script 使用，不用放上 GitHub）
- `images/`：地點照片、角色卡圖片
- `images/kv.svg`、`images/kv.png`：活動主視覺海報。活動日期 11/14（六）13:10–15:45，要修改可用 Illustrator 開 kv.svg

## 學生使用流程
1. 打開網站 → 載入動畫
2. 選自己走的路線，填班級座號和名字 → 出發（手機會詢問能不能使用位置，請按「允許」）
3. 進入義竹大地圖：三條路線、九個點、集合點都在圖上，藍色圓點是自己的位置，小怪獸停在「下一站」
4. 下方面板會顯示到下一站的距離；走到 60 公尺內，「我到了，集章！」按鈕才會亮起來
5. 集章後跳出角色圖卡，可以直接拍一張照片放進圖卡；收下圖卡後，小怪獸會走到下一站
6. 集滿三個章 → 小怪獸回到集合點，出現獎勵畫面，給工作人員看即可領獎
7. 地圖上也看得到其他路線同學的位置（每條路線一隻小怪獸，站點旁顯示人數）
8. 「我的資料夾」可以看到自己每一站拍的照片和上傳狀態

### 定位不準時：帶隊口令
定位在室內、樹下或訊號差的地方可能不準。帶隊人員到站後說出口令，學生點「帶隊口令」輸入，一樣可以集章。
- 口令在 `data.js` 的 `leaderCode`（目前是 1114），**活動前請改成你們自己的數字**，只告訴帶隊人員。
- 集章距離在 `stampRadius`（目前 60 公尺），可以依現場狀況調整。
- 試算表會記錄每次集章是「定位」還是「帶隊口令」。

### 網路不好時
照片和集章紀錄會先存在學生手機裡，有網路時自動補傳（也可以在「我的資料夾」按「立刻補傳」）。請提醒學生活動當天不要清除瀏覽紀錄、不要用無痕模式。

## 測試模式（不用到義竹也能測）
在網站網址最後加上 `#test`，例如 `https://你的帳號.github.io/yizhu-walk/#test`，按「用我現在的位置開始測試」。
- 網站會以你現在的位置建立三個測試點：A 就在腳下、B 在北邊約 90 公尺、C 在東邊約 90 公尺。
- 先在 A 集章，再往 B、C 走，確認距離會變小、走到 60 公尺內印章會亮起來、集章後小怪獸會移動。
- 測試資料和正式資料完全分開，按「結束測試，回到正式版」就會清掉。
- 如果已經設定上傳網址，測試的照片和集章紀錄會真的送到雲端（路線名稱是「測試路線」），測完請到雲端硬碟和試算表刪除。
- 建議 iPhone 和 Android 各測一支，並分別用 Safari、Chrome、LINE 開啟，比較差別。
- 定位一定要在 `https://` 網址下才能用，請用 GitHub Pages 的網址測，不要直接開電腦裡的檔案。

## 一、上傳到 GitHub 並開啟網站
1. 登入 GitHub，按右上角「+」→「New repository」。
2. Repository name 填 `yizhu-walk`，選 **Public**，按「Create repository」。
3. 按「uploading an existing file」，把 `index.html`、`data.js`、`README.md` 和 `images` 資料夾拖進去，按「Commit changes」。
4. 到「Settings」→「Pages」→ Source 選「Deploy from a branch」，Branch 選 `main`、`/ (root)`，按「Save」。
5. 等 1～2 分鐘，網址是：`https://你的帳號.github.io/yizhu-walk/`

## 二、照片上傳與即時位置設定（Google 雲端硬碟）
GitHub Pages 只能放網頁，不能收檔案，所以照片和集章紀錄透過 Google Apps Script 存進計畫的雲端硬碟。**學生不需要 Google 帳號**，只有設定的人需要用計畫的帳號登入。

1. 用計畫的 Google 帳號，在雲端硬碟新增資料夾「義起走讀照片」。打開它，網址最後那串英數字就是資料夾 ID（`https://drive.google.com/drive/folders/這一串`）。
2. 打開 https://script.google.com →「新專案」，刪掉原本的內容，貼上 `apps-script.gs` 全部內容。
3. 把 `ROOT_FOLDER_ID` 換成步驟 1 的資料夾 ID。`KEY` 可以改成你們自己的暗號。
4. 上方函式選單選 `testSetup` → 按「執行」，第一次會要求授權雲端硬碟和試算表，按允許。執行完成後，資料夾裡會出現試算表「義起走讀紀錄」。
5. 右上角「部署」→「新增部署作業」→ 類型選「網頁應用程式」：執行身分選**我**，誰可以存取選**所有人**，按「部署」。
6. 複製「網頁應用程式網址」（結尾是 `/exec`），貼到 `data.js` 的 `uploadUrl: ""` 引號裡；`uploadKey` 要和步驟 3 的 `KEY` 一樣。
7. 用瀏覽器打開那個 `/exec` 網址，看到「上傳服務運作中」就成功了。

設定好之後：
- 照片自動整理成 `義起走讀照片 / 路線一　古厝與信仰 / 80105_小明 / 翁清江古厝_時間.jpg`
- 試算表「義起走讀紀錄」每一列是一次集章：時間、路線、學生、地點、定位或口令、離地點幾公尺。活動結束後可以直接拿來統計參與人數和完成率。
- 地圖右上角會從「示範資料」變成「即時」，其他同學的位置每 30 秒更新一次（`liveRefresh` 可調）。地圖上只顯示名字，不顯示班級座號。
- 還沒設定前，地圖上的其他同學是示範資料，照片只存在學生手機裡。
- 修改 Apps Script 程式後要「部署」→「管理部署作業」→ 編輯 → 版本選「新版本」，網址才會更新。

## 四、更新內容
- 在 GitHub 點 `data.js` → 鉛筆圖示編輯 → 「Commit changes」，約 1 分鐘後更新。
- 地點照片：放進 `images`，在該地點 `image: ""` 填檔名。
- 角色卡：學生作品放進 `images`，在該地點 `card: ""` 填檔名。學生沒拍照時，圖卡會顯示角色卡；都沒有時顯示拼圖怪獸。
- 長輩訪談：填在 `elder: ""`。
- 獎勵說明：改 `reward` 文字。
- 內容查證完成後，把 `status: "draft"` 改成 `"ok"`。

## 五、注意
- 集章、名字、照片縮圖都存在學生自己的手機瀏覽器裡，換手機或清除瀏覽紀錄會不見；已上傳到雲端硬碟的照片不受影響。
- 集章是學生自己按的，無法確認是否真的到場，建議由帶隊人員確認後再按。
- 學生是未成年，照片資料夾請只開放給計畫人員；若要公開使用照片，先取得學校與家長同意，避免出現正臉與全名。
- 免費的 GitHub Pages 需要 Public 儲存庫，所以 `data.js` 裡的上傳網址和暗號別人看得到。暗號只能擋掉隨便亂傳的人，活動結束後可以到 Apps Script「管理部署作業」把部署封存，停止收件。
